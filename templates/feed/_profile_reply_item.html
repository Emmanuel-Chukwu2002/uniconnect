A "reply" here is just a Comment — whether it was a top-level comment on a post or a reply to another comment, both show up here, same as X's own Replies tab. Clicking it opens the full thread on the original post (the same modal a post's own comment icon opens) and scrolls straight to this comment, auto-expanding any collapsed "View N replies" it's nested under along the way (see app.js). Carries the same action row a post card has (like/comment/repost/ share/bookmark), styled identically (post-card-action-btn) but wired to the comment endpoints, since a reply is a Comment, not a Post: like toggles CommentLike, the comment icon opens this same thread (showing how many direct replies THIS reply has), repost is the same honest "coming soon" placeholder a post card uses, share copies a link to the underlying post, and bookmark links to Bookmarks the same way a post card's does. Those buttons live inside the whole-card click target above, so app.js stops their clicks from also re-triggering it (see the .post-card-actions click handler). Also carries the same 3-dot menu a comment gets in the full thread (_comment_item.html) — Edit/Delete only for the reply's own author (checked again server-side regardless), plus the same honest "Mute post" placeholder — but edits/deletes right here on the card instead of needing the full thread open, via its own endpoints (js-reply-edit-btn / js-reply-delete-btn in app.js) since this card's markup isn't the thread's .comment-item shape the existing js-edit-comment-btn/js-delete-comment-btn handlers expect. The comment icon doesn't just open the thread read-only — it opens it with this reply's own inline reply box already expanded and focused, so replying to it is a single click (js-reply-open-comments in app.js). When this reply has replies of its own, a "View N replies" row (same look as the thread's own collapsed-replies toggle, comment-view-replies) appears beneath the actions; clicking it opens the thread, scrolls to this comment and expands its children, instead of trying to render a second copy of the thread's nesting here. {% endcomment %}
